# החלטות הפרויקט (DECISIONS)

כל החלטה משמעותית שהתקבלה במהלך בניית Rewind, עם הנימוק. נכתב תוך כדי העבודה.

---

### D-001 · שפת שרת ומסגרת: Python 3.12 + FastAPI
- **מה בחרנו:** FastAPI + Uvicorn.
- **אפשרויות שנשקלו:** א) FastAPI ב) Flask ג) Django.
- **למה זה המומלץ:** FastAPI הוא ההמלצה המפורשת של המטלה, מספק `/docs` אוטומטי, ולידציה דרך Pydantic, ו-async מובנה שמתאים ל-PyMongo Async.
- **מה המחיר:** צריך הבנה של async/await.
- **הסבר בהגנה:** "בחרנו FastAPI כי הוא מהיר, מתעד את עצמו ב-OpenAPI, ומוליד ולידציה אוטומטית מ-Pydantic."

### D-002 · מסד נתונים: MongoDB 7 עם PyMongo Async
- **מה בחרנו:** `mongo:7` + `pymongo.AsyncMongoClient` (pymongo ≥ 4.10).
- **אפשרויות שנשקלו:** א) PyMongo Async ב) Motor (הוצא משימוש) ג) Postgres.
- **למה זה המומלץ:** MongoDB הוא ההמלצה. PyMongo Async הוא הדרייבר הרשמי והעדכני; Motor הוכרז deprecated לטובתו.
- **מה המחיר:** API חדש יחסית, פחות דוגמאות ברשת.
- **הסבר בהגנה:** "השתמשנו בדרייבר ה-async הרשמי של MongoDB. Motor היה הגיבוי אם היו בעיות."

### D-003 · מודל: v4_2 בדפדפן עם onnxruntime-web
- **מה בחרנו:** מתוך 9 המודלים, v4_2 (GRU + Attention), רץ בדפדפן.
- **אפשרויות שנשקלו:** v1–v4_7. ריצה בשרת מול בדפדפן.
- **למה זה המומלץ:** v4_2 מחזיר שלושה פלטים (regression, classification, attention) שמאפשרים גם ציון, גם רמה מילולית וגם משקלי attention לאנליטיקה. ריצה בדפדפן שומרת על פרטיות (וידאו לא עוזב את המחשב) ומורידה עומס מהשרת.
- **מה המחיר:** טעינת 15.7MB בדפדפן, תלות ב-WASM.
- **הסבר בהגנה:** "המודל רץ בדפדפן כדי שהווידאו לא ייצא מהמחשב; לשרת נשלח רק ציון מספרי."

### D-004 · תקשורת לקוח-שרת דרך reverse proxy של nginx
- **מה בחרנו:** הלקוח פונה ל-`/api/...` יחסי; nginx מעביר ל-`BACKEND_URL`.
- **למה זה המומלץ:** אין CORS, אין כתובת שרת קשיחה בקוד (דרישת המטלה: "כתובת השרת ניתנת להגדרה"), ומעבר לענן = שינוי משתנה סביבה בלבד.
- **מה המחיר:** שכבת proxy נוספת.
- **הסבר בהגנה:** "הלקוח לא יודע את כתובת השרת; nginx מתווך, אז מעבר לענן הוא שינוי של משתנה אחד."

### D-005 · סיסמאות: argon2id דרך argon2-cffi
- **מה בחרנו:** `PasswordHasher` עם ברירות המחדל (argon2id, time_cost=3, memory=64MiB, parallelism=4).
- **אפשרויות שנשקלו:** argon2id, bcrypt, scrypt.
- **למה זה המומלץ:** argon2id זכה ב-Password Hashing Competition, עמיד ל-GPU/ASIC, וכולל salt אקראי מובנה בכל hash.
- **הסבר בהגנה:** "argon2id הוא התקן המודרני; כל hash כולל salt אקראי משלו."

### D-006 · טוקן: JWT HS256 עם jti ו-tv
- **מה בחרנו:** PyJWT, HS256, exp=60 דק', כולל `jti` (לביטול) ו-`tv` (token_version, לביטול המוני בהחלפת סיסמה).
- **הסבר בהגנה:** "jti מאפשר logout אמיתי; token_version מבטל את כל הטוקנים הישנים כשמחליפים סיסמה."

### D-007 · לקוח: React 18 + Vite + JavaScript (לא TypeScript)
- **למה זה המומלץ:** JS פשוט יותר ללמוד ולהסביר בהגנה, בלי שלב קומפילציה של טיפוסים. Vite מהיר.
- **מה המחיר:** פחות בטיחות טיפוסים.
- **הסבר בהגנה:** "בחרנו JS כדי שהקוד יהיה נגיש להסבר; הולידציה האמיתית קורית בשרת ממילא."

### D-008 · עיצוב: CSS רגיל עם CSS variables (בלי Tailwind/UI kit)
- **למה זה המומלץ:** קל להבין ולהגן, בלי תלות חיצונית, שליטה מלאה ב-RTL.

### D-009 · פורמט חישוב הקטעים שהוחמצו בשרת
- **מה בחרנו:** כל לוגיקת החוב/קטעים/סגירה ב-`services/segments.py` כפונקציות טהורות עם בדיקות pytest. הלקוח רק מציג.
- **למה זה המומלץ:** אמינות (השרת הוא מקור האמת), ניתן לבדיקת יחידה, ולא ניתן לרמות מהלקוח.
- **הסבר בהגנה:** "הסגירה של קטע היא לוגיקה עסקית, לכן היא בשרת ולא בלקוח שאפשר לזייף."

### D-010 · הצגת ציון גולמי כראשי, מוחלק לחישוב
- **מה בחרנו:** ScoreCard מציג את הציון הגולמי האחרון (כפי שהמטלה מתארת), והציון המוחלק (EMA) משמש להתראות ולחישוב החוב, ומוצג כמשני.
- **הסבר בהגנה:** "המספר הראשי הוא מה שהמודל החזיר; ההחלקה מונעת התראות שווא."

### D-011 · אין פנים → לא מריצים מודל ולא שולחים מדידה
- **מה בחרנו:** כש-≥70% מהפריימים בשנייה האחרונה בלי פנים, מצב noFace, המודל לא רץ, אין POST. כשהפנים חוזרות ממשיכים למלא את החלון בלי לאפס.
- **למה:** מדידה בלי פנים חסרת משמעות; המשך מילוי (בלי איפוס) מחזיר ציון מהר כשחוזרים.
